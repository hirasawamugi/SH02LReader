# M2.5：代码与功能优化、EPUB 接入设计草案

日期：2026-10-20（Asia/Shanghai）。状态：供用户审阅，尚未进入产品实现。

本次修订：纳入用户明确提出的菜单/F 键重分工、列表首尾循环，以及未来多机型按键适配准备。第 4 节区分用户确认方向与由 Codex 提出的细节默认值；文档更新不代表软件已经实现。

基线：M2 `0.3.1-m2`，源码交付记录 `c171985`，APK 编译来源 `8d0df64`。本轮先审查源码并整理设计；未执行 EPUB 引擎试验、未新增依赖、未操作正式手机书库。

## 1. 目标与路线

用户要求新增 M2.5，再进行一次代码和功能优化，并将原 M4 的 EPUB 工作前移融合；之后根据实际情况进行 M3。成功标准是降低新增或调整功能时的维护成本，同时交付可日常使用的 TXT/EPUB 阅读流程。

建议顺序为 M2 → M2.5-A（盘点与 EPUB 可行性验证）→ M2.5-B（结构与功能优化）→ M2.5-C（EPUB 完整接入）→ M3（综合稳定性与性能验收）。A/B/C 是 M2.5 的内部交付检查点。原 M4 不再作为排在 M3 之后的独立 EPUB 阶段。

M3 的规模与启动时机结合 M2.5 交付情况决定；数据保护、按键、定位和升级检查随每次相关改动执行。长期试读仍由用户日常累计，不安排会话连续等待两小时。

## 3. 设计方向与数据边界

采用由 EPUB 实际需求驱动的渐进调整。先取得引擎在 SH-02L 上的有限可行性证据，再确定适配器契约，逐步迁移现有 TXT。先全面重构后选引擎容易返工；直接叠加 EPUB 会扩大现有格式耦合。

- `reader-core` 保存格式标识、元数据、目录、能力、定位与任务身份等无 Android UI 的契约。文档定位包含格式、定位版本和格式自身的载荷；百分比用于显示和跳转意图，不作为唯一永久定位。
- TXT 与 EPUB 引擎分别负责内容访问、目录、搜索和格式定位。TXT 保留现有归一化 UTF-16 偏移语义；EPUB 使用能随重排恢复的文档资源与内容锚点，具体载荷随选定引擎固定和版本化。
- Android 阅读界面适配器负责显示、翻页、应用排版、实际上屏位置、就绪回调和释放。共用层不要求两种格式共用 Canvas 页对象，也不把引擎专用类型暴露给普通菜单。
- 应用流程协调导航、原生输入、导入导出和状态提示。当前按键周期规则继续复用；阅读、菜单、输入及引擎 View 明确事件归属，关闭覆盖层恢复焦点。
- 机型配置将原始事件映射到逻辑键，页面上下文将逻辑键映射到动作；业务菜单、TXT/EPUB 引擎不依赖 SH-02L 硬件键码。机型名称、物理键标签及帮助图资料从配置读取，详见 4.4。
- 书库保存稳定书籍身份和格式；进度与书签保存版本化定位。旧 TXT 数据通过显式迁移继续使用，不以重导入、清库或重算旧偏移完成升级。迁移失败保留原有有效数据并报告问题。
- 原件、公共书库数据与格式缓存分开。复制/移动导入、完整核验、提交后删除来源和导出原字节的规则继续适用；缓存清理通过格式能力确认能否重建。
- 保留任务代次检查、删除时失效待写及已出队进度、低存储有限重试。跨会话或排版变化的过时回调不得覆盖当前画面或更新后的定位。

## 4. 已确认的优化方向与交互设计

用户确认的优先项为：书籍相关菜单和通用菜单分开并优化顺序；用 F2 承接原书架 F3 的导入入口，仅保留 F4 承担返回/退出当前层；列表首尾循环；在结构调整中为未来其他翻盖按键手机准备适配边界。用户授权 Codex 决定其余易用性细节。下列页面映射、菜单顺序与循环边界为据此提出的具体默认设计。

### 4.1 F1–F4 与页面上下文

| 场景 | F1 | F2 | F3 | F4 |
| --- | --- | --- | --- | --- |
| 书架选中一本书 | 该书的书籍菜单 | 导入图书 | 通用设置菜单 | 根层保持书架 |
| 空书架或选中导入/分页等非书籍项 | 不打开书籍菜单，提示当前未选中图书 | 导入图书 | 通用设置菜单 | 根层保持书架 |
| 阅读正文 | 当前图书的阅读操作菜单 | 导入图书，取消时回原正文 | 通用设置菜单 | 返回书架，保存阅读进度 |
| F1/F3 根菜单 | 切换到书籍/阅读菜单；再次按同一菜单键关闭该菜单 | 无额外动作 | 切换到通用设置菜单；再次按同一菜单键关闭该菜单 | 关闭最上层并恢复原焦点 |
| 目录、书签、设置、文件选择等子页 | 仅执行本页明确提示的动作 | 仅执行本页明确提示的局部动作，不作为返回键 | 仅执行本页明确提示的动作 | 返回上一层 |
| 原生文本/数字输入 | 依输入上下文 | 不再用作取消 | 确认输入 | 取消并返回，保留原定位 |
| 应用内导入/搜索等任务页 | 依本页提示 | 不作为返回/取消键 | 依本页提示 | 取消当前可取消任务并返回 |
| 按键帮助 | 无额外动作 | 不作为返回键 | 无额外动作 | 关闭帮助并恢复原页面 |

F2 在正文导入属于便利性默认值，书架导入是用户明确要求；进入导入前保存原会话与定位，F4 取消不误跳书籍。F4 的“退出”解释为返回/关闭当前层；退出整个应用保留在 F3 的明确入口并二次确认，根书架不因 F4 直接退出。

两种根菜单切换时替换同一层，不叠加菜单，来源书籍 ID 与原选择位置保持不变。子页面、输入和正在提交的流程不被全局菜单快捷键打断。无动作的功能键在应用收到时明确消费，避免落到系统外部功能；系统保留键维持系统语义。

数字和方向键在原生输入中继续交给输入框/输入法，不能触发阅读快捷键；F3/F4 在事件实际交到应用时执行确认/取消。实际中文输入法的候选与提交行为单独真机验证。0 的帮助开关、正文数字/星号/井号快捷键继续保留，帮助正文仍使用滚动语义。

### 4.2 菜单内容、顺序与焦点

关闭/返回置于菜单首项，F4 可随时直接返回；打开菜单默认选中首个常用操作，避免默认执行关闭或危险操作。删除和退出应用放在所属菜单末尾，并保留确认，确认层默认取消。只有可执行的项目进入选择序列。

| 菜单 | 从上到下的默认顺序 |
| --- | --- |
| 书架 F1 书籍菜单 | 关闭菜单 → 设置/更换封面 → 重命名图书 → 导出原书 → 导出封面原图（有封面时）→ 移除自定义封面（有封面时）→ 删除图书及私有数据 |
| 正文 F1 阅读菜单 | 关闭菜单 → 目录 → 书签 → 返回书架 → 搜索正文 → 跳转阅读进度 → 纠正文本编码（仅 TXT） |
| F3 通用设置菜单 | 关闭菜单 → 阅读设置 → 导入图书 → 存储管理 → 按键说明 → 按键诊断 → 退出应用 |

“阅读设置”继续包含界面外观与正文阅读两个设置分组，保留当前主题、书架样式、字体等功能。F3 菜单不混入所选图书的封面、重命名和删除操作；F1 菜单不混入通用设置与诊断操作。关闭/取消/返回是导航项，不属于两类业务操作混排。

“导入图书”和“导出原书”是多格式通用名称；界面说明标明支持的 TXT/EPUB，导出保持原格式、后缀与原始字节。EPUB 接入前实际可用格式仍只有 TXT。编码纠正等格式特有功能通过能力表控制。

菜单项使用稳定动作 ID 与声明式顺序，是否可用、目标图书和执行动作由同一上下文计算。异步封面元数据只更新对应固定位置，不将项目临时追加到选框附近；更新后保持实际选中动作 ID。目标书籍已删除或会话已切换时取消旧动作并返回合理页面。

底部软键提示和按键帮助使用同一份动作解析结果。为清楚容纳四个 F 键，默认使用两行、两列提示（F1/F2，F3/F4）；机型配置可提供物理标签和排列。调整提示区高度时保持正文锚点并复核分页，不恢复已废弃的 F2 返回/F3 书架导入说明。

用户补充要求（2026-10-20）：每次改变功能、菜单或按键映射，都同步更新对应位置的底栏、页面说明、输入按钮、任务取消/错误提示以及按键帮助图与文字，确保实际动作、当前上下文和显示文案一致；不能只改分派逻辑，遗留旧提示。后续 EPUB 新增或调整入口同样执行此要求。

当前按键说明页的观感不佳，纳入 M2.5 明确的排版优化项。在新映射与功能稳定后、候选交付前统一整理键帽和说明的对齐、文字层级、间距、分组与长文换行，保持机型物理布局及键位说明对应正确。在 SH-02L 实际屏幕与现有字体比例下目视检查，不修改系统字号来迁就布局；文字、图形及软键不得重叠、裁切或过度拥挤。未来机型的文字回退说明沿用同一套排版规则。

### 4.3 列表首尾循环

- 当前逻辑列表第一项向上到最后一项，最后一项向下到第一项；短按和允许的重复移动使用同一规则。空列表不移动，单项列表保持该项，不产生除零、重复激活或焦点丢失。
- 循环按可选项计算，跳过加载、说明、不可用等非操作行。每次移动只更新一份真实选择状态，选框、确认对象和可见滚动位置一致；跨首尾立即显示目标项。
- 普通条目间移动继续使用已确认的“页面内移动选框，越过可视边界才滚动”规则；返回父页仍恢复条目与像素位置，包括布局前连续按键。
- 书架按当前加载的批次循环，上一批/下一批入口继续保留，不为循环加载全库或偷偷跨批；目录、菜单、书签、设置和文件列表使用同一选择策略。
- 正文前后翻页、章节边界、帮助正文滚动、数值调整及输入光标不使用列表循环。删除当前项后选择相邻有效项，只有真实的方向移动触发首尾循环。

### 4.4 面向未来机型的按键适配

目标产品面向翻盖按键手机，SH-02L 是首个已验证配置。当前阶段建立扩展接口并迁移现有机型，不宣称其他机型已经适配。

按键链路为：原始事件（keyCode/scanCode/deviceId/Down/Up/Repeat）→ 机型映射 → 逻辑键与完整按键周期 → 当前页面动作 → 操作执行。机型特例只进入配置/映射层，通用菜单、导航及 TXT/EPUB 引擎不添加型号判断。

机型配置持有配置 ID/版本、设备匹配信息、物理键到逻辑键映射、经记录的 scanCode 回退规则、保留键规则、显示标签与可选帮助布局。SH-02L 的映射继续以 `device/sh02l按键值.txt` 为依据。标准 keyCode 优先，scanCode 仅在该配置明确允许的异常情况下使用，未知键保留诊断信息，不凭猜测映射。

同时准备配置注册/选择、未来用户覆盖项的存取接口和恢复默认配置边界。默认配置与用户覆盖分开并版本化，未知机型先提供标准键及诊断回退，未明确匹配时不冒充 SH-02L。适配选择或覆盖变更时清除未结束按键状态，整次 Down/Repeat/Up 使用同一映射快照；按键身份区分设备与物理来源，避免不同物理键映射到同一逻辑键时串用周期。

帮助图与软键名称不继续绑定 SH-02L 的几何和相机/邮件等印字。具备布局资料时显示对应图，无布局资料时显示文字表。诊断记录包含当前配置、原始事件、逻辑键与最终动作，便于以后依据真实键值新增机型。

本轮不增加缺少实测资料的其他机型，不强制新增完整的自定义按键编辑器。未来的“机型/按键适配设置”接入上述选择与覆盖接口；无需重写菜单或格式引擎。

### 4.5 其他优化候选

搜索结果返回、继续查找、排版加载反馈、待保存与失败提示仍可随相关流程优化，具体行为变更单独记录。整库备份、网络书源、同步和朗读不由本次优化自动扩展引入。

## 5. EPUB 建议范围与选型条件

首批建议面向本地、无 DRM、可重排的 EPUB 2/3，使用真实中文图书及受控测试书验证。最低阅读流程包括安全导入、元数据/封面、目录、前后翻页、章节与内部链接跳转及返回、排版/主题、书签、关闭重开后的进度恢复、正文搜索与结果跳转，以及现有实体按键操作。

图文需要有界加载并处理图片尺寸；未知或不支持的内容明确提示。固定版式、脚本交互、多媒体和 DRM 不列入首批验收范围。若选型发现上述最低流程无法实现，先具体说明差距并修订设计，不默认为已支持。

现有设备记录确认 Android 8.1/API 27、540×960、240 dpi、32 位 ARM；尚未在本轮核实当前 WebView 版本，也没有新的 EPUB 运行证据。原调研中的 Readium/CoolReader 可作为候选入口，历史快照不代表当前版本已经适用。

选型前查阅候选正式版本的官方资料，核对 API/ABI、依赖、定位和排版能力、许可、包体及内存开销；使用隔离测试包验证一个真实 EPUB 的显示、按键翻页与重开恢复。记录准确版本与证据后再锁定引擎和接口细节。此验证在设计与执行计划审阅完成后进行。
