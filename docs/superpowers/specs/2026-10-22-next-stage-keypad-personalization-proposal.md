# M4：按键体验、文件整理与个性化实施方案

方案日期：2026-10-22。2026-11-08 用户已确认实施 01–04，并将本阶段命名为 **M4**；05、06 后续推进，其余暂缓。当前状态：实施中。

本方案基于 `main` 的 M3 实现、已有真机记录和用户反馈编写。文中的目标和预算不表示已经实现或通过验证；实施及验证结果单独记录。沿用正式包名与签名，完成后交付一个 M4 整合试用版本。

## 1. 目标与范围

面向 SH-02L 等旧按键手机，优先改善日常操作与文件管理，并开始支持个人主题。主要阅读用途是长篇小说和网文。产品理念为“每个人有每个人的阅读器”：操作规则保持清楚，外观允许多种审美。

设计与验证以已记录的 SH-02L 基线为依据：Android 8.1 / API 27、540×960、240 dpi、系统字号比例 1.3、系统 WebView 67。实现前重新读取实际设备版本，使用设备支持的原生能力。

| 编号 | 本阶段交付范围 |
| --- | --- |
| 01 | 优化重复导入的处理顺序；改善单书导入反馈与目录返回；增加按书清理正文缓存；统一现有文件管理入口和新背景资源的回收。 |
| 02 | 修正书架左右不对称；移除帮助页滚动条；统一列表滚动指示和按键提示；补充按屏移动、目录序号定位与常用菜单顺序。 |
| 03 | 自定义静态书架背景、按键裁剪预设、遮罩强度和应用界面配色；提供预览、保存、取消及恢复预设。 |
| 04 | 增加纯阅读模式；保持内容锚点与原有阅读操作；优化控件显隐、重排和任务合并。 |

05 轻量书架管理、06 排版与目录内容优化留待后续。其余候选暂缓，包括备份、本地小说续更、批量导入、全局图片背景、正文图片背景、逐书设置、扩展回查与主题包导入导出。

02 中的“目录序号定位”仅定位已有目录项，不修改章节识别规则，不新增目录全文检索。03 的界面颜色用于书架、菜单和设置；背景图片仅用于书架。正文继续使用独立的现有阅读配色。

本阶段沿用 Java、原生 Views / Canvas、系统 WebView 和现有模块。功能按下面的顺序整合，最终形成一个候选版本。

## 2. 滚动条问题：调查结果与修正设计

### 2.1 已确认的代码事实

- `NavigationListView` 构造时固定设置右侧 12 dp 内边距，左侧为 0。滚动条是否可见都不会移除这块留白。
- 普通页面外层又为左右各设置 12 dp 边距。因此，列表项相对页面中心存在额外的右侧空白；仅把滚动条隐藏不能解决这个问题。
- 列表样式使用 3 dp 的原生覆盖式滚动条。额外空白主要来自显式内边距，并非滚动条绘制宽度本身。
- `KeyHelpView` 是自绘的按键说明页，并非列表。它在说明内容高于视口时单独绘制右侧细条；已有截图也能看到这个细条。
- 帮助页实际支持上下浏览长说明。移除滚动条时，需要让超出屏幕的说明仍然可达。
- 旧的 `ListNavigationTest.testScrollbarHasSpaceBesideTheSelectedRow` 明确要求右侧预留空间。实施时应替换为新的几何验收，避免旧断言继续锁定有问题的布局。

以上为代码与已有截图核对，本次没有操作真机，也没有宣称修正后的视觉效果已经验证。

### 2.2 推荐的几何规则

1. 书架列表项左右外边距均为 12 dp；取消列表内部单边额外预留的 12 dp。
2. 菜单内列表相对所在面板同样左右等距；外边距只由一层容器负责，避免叠加。
3. 列表内容超过视口时，使用约 2 dp 的细指示条，覆盖绘制在右侧外边距内，不参与列表项宽度计算。
4. 指示条在可滚动列表中保持静态可见，随列表位置更新；内容一屏可见时隐藏。显示或隐藏均不改变列表项宽度，不使用淡入淡出动画。
5. 选中背景始终以内容区域为准，保持居中，不随指示条出现而横向移动。
6. 帮助页完全移除右侧滚动条。减少重复说明；只在内容超出时显示简短的“↑↓ 浏览说明”。内容能完整显示时不显示滚动提示。底部仅显示“0 / F4 关闭”，不再用两行展示未启用的 F 键空项。
7. 帮助页不通过缩小关键按键文字强行塞进一屏；`0` / `F4` 关闭并恢复原位置的行为继续有效。

实现优先使用原生覆盖绘制和现有容器；若需要单独的指示绘制层，它仅消费滚动范围与位置，不拥有第二套列表选择状态。

## 3. 按键设计

### 3.1 基础规则

不引入双击、组合键或新的长按功能。方向键重复事件继续由现有 `KeyRouter` 处理；开关和确认动作不可因按住而连续触发。

| 场景 | 按键 | 拟定动作 |
| --- | --- | --- |
| 书架 | ↑ / ↓ | 逐项选择，继续使用已有的首尾循环规则。 |
| 书架、目录、文件列表、管理列表 | ← / → | 上一屏 / 下一屏；移动到相应可见位置，到边界停止，不循环。书架原有分批加载入口继续可用。 |
| 书架、目录、文件列表 | 确认 | 打开选中内容。 |
| 书架 / 正文 | F1 | 所选书籍菜单 / 阅读菜单。 |
| 书架 / 正文 | F2 | 导入图书。再次进入时尽量恢复最近的有效来源目录和选择。 |
| 书架 / 正文 | F3 | 通用菜单。 |
| 普通页面 | F4 | 返回上一层；正文返回书架；书架根层保持原行为。 |
| 目录 | F1 | “按目录序号定位”，进入数字输入。序号按实际目录项计数，不把它冒充书中的章节编号。 |
| 设置、外观编辑 | ↑ / ↓，← / → | 上下选择参数，左右调整参数；不执行列表按屏移动。 |
| 清理选择列表 | 确认，F3 | 确认键勾选 / 取消勾选；F3 进入所选项目的清理确认页。 |
| 外观编辑根页 | F3 / F4 | 保存并应用 / 放弃本次编辑并返回。 |
| 外观子页、文件选择页 | F4 | 返回外观草稿，保留尚未保存的草稿内容。 |
| 文本 / 数字输入 | F3 / F4 | 提交当前输入 / 取消当前输入；不越级提交整个外观草稿。 |
| 正文 | 8 | 普通模式 ↔ 纯阅读模式。 |
| 普通页面 | 0 | 按键说明；输入时仍用于输入。帮助页用 0 / F4 关闭。 |

正文的方向键、确认、1/3 切章、2 目录、4/6 字号、5 阅读配色、7/9 亮度、`*` 设置、`#` 书签继续有效。

**需要用户审阅的按键变化：**将 `8` 从“信息栏开关”改为“纯阅读开关”。信息栏开关移到阅读设置，保留原先选择，并仅在普通阅读模式下生效。帮助图、菜单和屏幕提示同步更新。

所有新上下文的提示都从相同的动作规则生成；不能出现 F3 实际保存，而屏幕仍写“通用菜单”的情况。

### 3.2 菜单与反馈

- 通用菜单建议顺序：界面外观、阅读设置、存储管理、导入图书、按键说明、按键诊断、退出。导入也可由 F2 直达。
- 阅读菜单的目录、书签和搜索靠前，新增纯阅读开关；原有格式专用功能继续按能力显示。
- 打开普通菜单时默认选择第一个可执行的常用动作。删除确认仍默认选中“取消”，用方向键选择“确认”后按确认键执行；F3 不跳过这一步直接删除。不将常用菜单的选择规则套到破坏性操作上。
- 关闭菜单、帮助或文件夹后，恢复条目身份和视口位置；异步更新不能把焦点跳回首项。
- 无消息时不保留空白提示行。重要失败信息必须可见，不能因为纯阅读模式隐藏提示区而消失。
- 长标题只在选中且前台有焦点时滚动一轮，之后停止；切换选择可重新查看，后台不继续滚动。

## 4. 01：导入与清理

### 4.1 单书导入流程

用户操作：`F2 → 最近有效目录/来源页 → 选书 → 复制或移动 → 后台处理 → 打开图书并显示简短结果`。

- 第一次仍展示来源页。之后记住最近使用的目录；路径失效、内存卡移除或权限不可用时返回来源页，不反复扫描整机。
- 复制/移动明确说明来源文件是否保留。新文件默认选择复制，不静默继承上一次的移动选择。
- 成功后延续当前自动打开图书的行为，提示来源已保留、已移走或因权限原因保留。
- 失败或取消时返回可继续选择的位置，说明哪些步骤已完成。已提交的图书不能被错误报告为完全未导入。
- 本阶段处理单本导入。清理已有多选能力与“批量导入”是不同功能，后者继续暂缓。

### 4.2 提前结束重复导入

当前 TXT 流程在原件保存、解码和索引完成后才检查书库中是否存在同一内容。拟调整为：

`流式写入暂存原件并计算已有内容哈希 → 查重 → 新书才解码/解析并建索引 → 原件发布与书目提交`。

- 复用原件保存时已有的哈希计算，不为查重额外增加一轮全文件扫描。
- 同内容已存在时，核验既有私有原件后返回已有书籍；保留书名、编码纠正、进度、书签与封面。
- 重复导入仍可能需要读取所选来源并写入暂存原件，收益重点是跳过后续解码、索引和缓存生成。
- 移动导入仍须在私有原件有效、来源身份未变化、允许删除时才删除所选来源。
- 保留 M3 已有的发布/事务恢复边界。无法确认已提交状态时不得直接清除恢复所需文件。

### 4.3 清理入口

存储管理统一展示：图书原件、正文缓存、封面、字体、背景资源、导入文件夹及可用空间。已有分类继续复用，各类文件由自己的负责模块处理。

| 操作 | 具体行为 |
| --- | --- |
| 清理正文缓存 | 按书勾选，显示预计释放量；保留原件、进度和书签；当前打开书籍不可选，并说明原因；再次打开时按需重建。 |
| 清理导入文件夹 | 只展示应用管理的导入目录中可处理的文件；默认不勾选；不扫描或批量删除用户的公共 Books 目录。 |
| 删除图书 | 沿用已有的原件、缓存、封面、进度及书签联动删除；确认页清楚列出范围。 |
| 移除自定义背景 | 原子切回有效的纯色配置后，回收不再使用的背景资源。 |
| 暂存和旧资源恢复 | 在对应操作收尾及启动恢复阶段处理；只回收明确无引用的文件，不建立常驻清理任务。 |

空间统计仅在进入存储页、用户刷新或操作结束后更新。统计大小不需要逐文件重算内容哈希；真正清理正文缓存前继续核验可重建原件。

清理结果区分成功、跳过、失败和仍未处理的项目。已完成部分如实保留，失败不会被误报成全部成功。

## 5. 03：静态书架背景与配色

### 5.1 首版可配置内容

入口：`F3 → 界面外观`。

- 基础配色：保留现有三套方案，增加少量静态配色起点，例如青绿、深紫等，允许继续调整。
- 背景：纯色 / 选择一张本地静态图片。使用已有可按键操作的文件选择与授权能力。
- 导入时裁剪：铺满裁切 / 完整显示；居中、靠上、靠下、靠左、靠右等离散位置预设。
- 遮罩：无、浅、中、深几个档位；以实际预览判断文字可读性。
- 配色参数：背景、面板、主文字、辅助文字、强调、选中底色等语义颜色。先提供颜色色块列表及分档明暗调整，不要求在小屏上输入十六进制值。
- 保留已有纯文字、小书标、独立封面三种书架样式；本阶段不新增网格布局。

初音或动画主题可以使用用户自己的背景素材与配色表达。首版不捆绑特定角色素材，不增加动画、动态模糊或背景轮播。

### 5.2 编辑与保存

1. 进入编辑器时复制当前配置为草稿。
2. 上下选择参数，左右调整；确认键进入图片选择、颜色列表或预览。
3. 预览展示真实书架结构、选中项和软键提示，方便判断背景是否影响阅读。
4. F3 完整保存并应用一次；F4 从编辑根页放弃草稿。子页返回仅返回草稿。
5. 损坏图片、超限图片或写入失败时维持原方案，提示重新选择。

建议首版只保存处理后的适屏背景成品，导入的高分辨率暂存原图在保存/取消后清理；不建立主题原图收藏库。**因此，保存后重新改变裁剪位置需要重新选择图片。**遮罩与颜色仍可直接调整。这是为减少手机存储占用做出的明确取舍，可由用户在审阅时修改。

图片导入使用复制语义，不删除用户选择的来源图片。

### 5.3 背景资源提交

先在暂存位置生成并验证新成品，再发布资源并原子切换配置引用，最后回收旧资源。配置写入失败继续使用旧背景；进程中断后按有效配置引用恢复。草稿、活动背景与未引用的旧文件有明确的归属和回收路径。

主题配置使用稳定 ID 和版本号，旧三套主题从当前整数值显式迁移。书库数据库预计保持 v3；主题及纯阅读设置不进入书籍数据表。

## 6. 04：纯阅读模式

### 6.1 产品行为

- 正文短按 `8` 切换；阅读菜单和阅读设置也有明确入口。
- 纯阅读隐藏书名、普通信息栏、常驻软键说明和空提示区，保留用户已有正文边距。
- 模式作为全局阅读偏好保存，重新打开书籍时恢复。它不影响书架、输入或菜单界面。
- F1/F3/0 等仍直接打开相应覆盖层。关闭覆盖层后回到原模式，不需要再切换一次。
- F4 在覆盖层中返回上一层；在正文中仍返回书架，不增加“先退出纯阅读、再按一次才返回”的特殊规则。
- 普通通知以不抢焦点的覆盖提示展示；保存失败等重要信息在纯阅读中也必须可见。

### 6.2 流畅度实现

- 让专门的阅读容器持有书名、正文、信息和软键区域；显隐一次性更新，保持同一个阅读会话与渲染 View。
- 切换前捕获当前内容定位，按新视口排版；确认该内容在新页仍可见，不要求重排后页首数值完全相同。
- 连续快速切换只接受最后一次目标模式，过期布局结果不能发布位置或覆盖新画面。
- 菜单与帮助继续使用覆盖层，不缩小正文视口，不因打开/关闭菜单重复分页。
- 布局改变时，只做当前有界窗口或 EPUB 当前资源需要的重排；不做整书预分页。
- 区分绘制参数与布局参数：改颜色尽量只重绘；改变字号、行距、视口大小才触发重排。
- 新布局发布前继续使用可用旧内容或同配色过渡，避免不必要的白屏；不以长时间冻结旧内容掩盖加载失败。

TXT 和 EPUB 的实际切换成本不同，分别测量。是否“丝滑”以真机按键到正确画面、内容稳定性和快速操作结果判断。

## 7. 性能、内存与耗电控制

下面是拟定预算与行为约束，尚未实测。

| 项目 | 控制方式 |
| --- | --- |
| 正常书架背景 | 只保留当前背景的有界解码缓存。540×960 的 ARGB_8888 像素约 1.98 MiB，正常新增背景像素预算约 2 MiB。 |
| 图片编辑峰值 | 初始将应用自行持有的背景相关位图合计限制在 8 MiB 内，涵盖旧图、候选图及临时处理；不等同于整个进程的额外 PSS。必要时降低预览分辨率。 |
| 图片解码 | 读取尺寸后降采样；采用 API 27 已支持的 BitmapFactory 路径，不先解码原始大图再缩小。首版沿用静态图片校验，来源文件上限建议 32 MiB。 |
| 图片工作队列 | 一个运行任务、最多一个最新候选；取消、离开编辑和切换图片使过期结果失效；不按图片数量创建线程。 |
| 正常按键和翻页 | 不在主线程做文件统计、哈希、图片解码或正文 I/O；焦点变化尽量只更新受影响的条目，不重建整个页面。 |
| TXT 缓存 | 保持现有最多 16384 UTF-16 单元/布局、3 个布局窗口、1024 个偏移范围，不为纯阅读扩大整书缓存。 |
| EPUB | 保持单阅读 WebView、现有归档边界与资源限制；同一资源的视口变化优先重排，不重新打开整本书。 |
| 静置 | 静态背景不产生持续动画帧；长标题滚动一轮停止；不定时扫描目录、自动清缓存或轮播主题。 |
| 后台 | 停止界面动画与无用刷新，取消已无用途的预览任务；通过现有生命周期和低内存回调释放可重建资源；保留需要完成的数据提交。 |
| 亮度与唤醒 | 主题和纯阅读模式不自动修改用户亮度选择，不新增常亮或后台唤醒机制。 |
| 清理策略 | 使用后仍可能复用的少量缓存允许保留；空间回收按需进行，避免频繁清空导致重复解码与读盘。 |

Android 位图的像素内存与图片文件体积不同；解码和图形缓冲还会有额外开销。预算需结合真机总 PSS 及相关图形/原生内存核对。[Android 位图文档](https://developer.android.com/topic/performance/memory/guide/bitmaps)

减少无必要的布局遍历和重绘也是重点，但不会在没有证据时把全部界面重写。[Android 自定义视图优化](https://developer.android.com/develop/ui/views/layout/custom-views/optimizing-view)

短时间采样用于发现后台空转、重复解码和持续重绘，不据此承诺电池续航提高多少。耗电体验继续结合自然使用观察。

## 8. 代码职责安排

保留 `app → engine-txt / engine-epub → reader-android → reader-core` 的依赖方向，不新增重量级框架或 Gradle 子项目。

下面列出的新类名是建议名，现有能力优先扩展；不因命名而重复建立职责相同的模块。

| 位置 | 调整内容与职责 |
| --- | --- |
| `InputBindings / KeyRouter / MenuCatalog` | 定义新上下文、按屏移动、外观保存/取消与纯阅读动作；动作、软键提示和帮助标签来自一致规则。 |
| `NavigationListView / UiStyle / SoftKeyBar / KeyHelpView` | 处理对称几何、滚动指示、选框、长标题和帮助页显示；不读写文件或数据库。 |
| `ImportExportController / DocumentImportRegistry / TextImporter` | 将原件暂存与内容身份计算，和格式解码/索引准备分为清楚的阶段；保持格式边界。 |
| `BookRepository / StorageManager / LibraryFeatures` | 负责书目提交、重复处理、按书清理、文件恢复及管理页面；存储规则不散落到 Activity。 |
| 新 `ThemeSpec`，扩展 `AppearanceStore / Palette` | 表达语义颜色、主题 ID、版本和背景引用；加载时一次解析为不可变配置，保留旧设置迁移。 |
| 新 `BackgroundStore / BackgroundLoader` | 分别负责背景文件提交/回收和有界异步加载；从现有封面代码提取真正共用的尺寸检查、降采样等辅助能力，不混用封面与背景文件目录。 |
| 新 `AppearanceFeatures` | 负责外观草稿、参数页面、预览和应用，不向 MainActivity 增加大量外观分支。 |
| 新 `ReaderChrome` 或同职责容器 | 持有正文周围控件并切换显隐；纯阅读 UI 状态与实际文档位置分开管理。 |
| `ReadingController / ReadingSurface / ReadingStyle` 与两种引擎 | 继续拥有阅读会话、定位、过期任务保护；按需补充绘制/布局差异判断，不把 TXT/EPUB 专用逻辑移回 app。 |
| `MainActivity` | 保留生命周期、权限/文件选择回调和组件装配；新功能经相应模块接入。 |

结构验收：增加一种配色主要修改配置；增加一个背景不修改分页逻辑；修改文件清理不触碰渲染器；纯阅读开关不创建第二套进度保存逻辑。

## 10. 验证与完成标准

### 10.1 有针对性的功能验证

| 范围 | 主要验证内容 |
| --- | --- |
| 列表几何 | 少量和溢出条目时，列表项左右外边距一致，像素取整差不超过 1 px；指示条显隐不改变条目宽度；旧右侧留槽断言改为这些行为。 |
| 帮助与焦点 | 无右侧滚动条；底部说明仍可达；关闭后选择与视口恢复；8 键标签正确；数字输入上下文不被抢键。 |
| 导入 | 新书、重复书、复制、移动来源无法删除、取消、提交边界中断；重复导入保留既有元数据且跳过新缓存生成。 |
| 清理 | 只清选中缓存、保护当前书、原件异常时不丢唯一可用内容；按实际结果报告部分失败；主题暂存不污染书库目录。 |
| 外观 | 明暗两类背景、超大/损坏图片、快速切图、取消草稿、写入失败与重启恢复；三种已有书架样式各选代表性检查。 |
| 纯阅读 | TXT/EPUB 模式切换、快速连续操作、菜单与帮助覆盖、保存失败提示、返回书架与重开定位；检查内容锚点和过期结果。 |
| 兼容迁移 | 现有三套配色、封面、字体、书籍、进度和书签在升级后仍有效。 |

逻辑和状态规则优先使用现有 JVM 测试；实际布局、文件事务及旧 WebView 行为使用隔离 debug 包和 SH-02L。视觉效果保留少量针对性截图，避免全部配色、字号和页面组合穷举。

已有测试覆盖且实现未变化的边界复用其证据；发生新失败或新修订时补充定点复核。不会为了凑数量添加只重复实现细节的测试。

### 10.2 轻量性能观察

- 用同一台设备、同样的书籍和阅读设置对照 M3。
- 初始采样建议：20 次列表/菜单操作，TXT 与 EPUB 各 20 次翻页、各 10 次纯阅读切换，以及反复返回书架后的少量内存样本。
- 区分首次加载、后台工作完成和实际可绘制状态，不能把测试轮询或 ready 消息耗时当作真实帧时间。
- 检查背景没有重复解码、切换没有累积多个阅读 View、内存没有随每次往返持续增长。
- 各做一段约 30 秒的前台静置和后台观察，检查本轮引入的持续任务；这不构成长时间耗电结论。
- 明显的按键响应、翻页或内存回退先定位；不为达到表面流畅扩大无界缓存。

不追加历史完整 P95、100/1000 本规模、长时间循环或多设备全矩阵。合盖、来电及长期体验继续依据用户自然试读反馈，必要时做问题定点检查。

## 11. 本稿中特别需要审阅的取舍

1. 列表采用左右等距、按需显示的覆盖式细指示条；帮助页彻底去掉滚动条。
2. `8` 改为纯阅读开关，信息栏开关留在阅读设置。
3. 首版图片只作用于书架，界面颜色可统一应用；正文保持独立配色。
4. 首版保存适屏背景成品，重新裁剪需要重新选图，以控制原图存储占用。
5. 本阶段保持单本导入和一套自定义外观配置，主题方案库及批量导入后续再做。

以上取舍随用户对本方案的确认进入实施；后续若收到新反馈，在此记录对应调整。
