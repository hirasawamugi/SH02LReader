# TXT 引擎与数据约定

运行时只依赖 Android 框架。M2.5 新增 `reader-android` 阅读界面/样式契约，TXT 与独立 `engine-epub` 实现相同的文档契约。`reader-core` 处理按键周期、流式文本和版本化定位；app 组合引擎、书库与界面，不把 EPUB 位置解释为 TXT 字符偏移。职责入口见 [代码结构](CODE_STRUCTURE.md)。

M3 的 TXT 读取窗口不再充当显示分页边界：窗口尾部未完成页接续读取，通常 8192、最多 16384 UTF-16 单元/布局，只留 3 个布局窗口与最多 1024 个偏移页范围。章节起点可作为当前页起点，复用已有索引；数据库仍为 v3、TXT 定位仍为 txt-v1。升级或布局变化时页首整数可重新对齐，内容锚点应保留可见，不把页首变化解释为源文件改写。

M2.5 数据库 v3 增加 format、locator_payload 和 progression，并为书签存储独立格式/版本/定位。v1/v2 的 TXT ID、offset 和书签标签原样迁入，TXT v1 仍以 UTF-16 单元定位。旧 offset 对 EPUB 只供兼容书架百分比显示；恢复、目录、搜索与书签使用 `epub-v1` 的资源路径、DOM 文本偏移和可选片段。显示百分比不能替代内容锚点。

EPUB 原件仍为 `original.bin`，不生成 `text.u16` / `index.bin`；系统 WebView 的页面排版在内存中进行，可回收。归档不解压到磁盘，不允许资源越过该书的归档边界。书籍展开总大小/原件各 256 MiB、条目 20,000、单篇正文 4 MiB、单资源 8 MiB；外部实体、书内脚本和外部资源关闭。没有清理 EPUB 原件作为“可重建缓存”的入口。

## 导入与文件布局

应用私有目录 `files/books/<原始文件 SHA-256>/` 保存：

| 文件 | 内容 |
| --- | --- |
| `original.bin` | 导入文件的原始字节，来源文件不会被改写 |
| `text.u16` | 无 BOM 的 UTF-16LE 正文缓存，CRLF/CR 统一为 LF |
| `index.bin` | 带 magic/version 的有界章节索引、编码、源大小与正文长度 |
| `cache.sha256` | M2 增加的正文缓存校验值；旧缓存按需渐进补充 |

先写 `.import-<UUID>` 临时目录，刷新文件后整体重命名，再用 SQLite 事务登记书籍。启动清理未完成的临时目录。提交时已经发布的完整文件会完成短事务；在该边界取消时，可能保留一本已完成导入的图书。

内容相同的原始字节使用同一 ID，重导入保留原进度；同名但内容改变的文件是不同图书。数据库、索引和位置均在应用内，不依赖持续持有原文件、内存卡或文档提供程序的权限。

复制、编码识别、归一化、索引、文件浏览、数据库访问与排版都在后台进行。取消/切书/重排更新任务代号；只有当前代号能提交显示结果。排版/加载执行器最多有一个运行任务和一个候选任务。进度独立串行写入，仅合并同一本书尚未开始的旧位置。

## 编码与内存上限

BOM 优先；无 BOM 时验证整个输入是否为严格 UTF-8，失败后使用严格 GB18030。支持带 BOM 的 UTF-16LE/BE，GBK 作为 GB18030 的兼容子集。不能确定的编码需要 M2 的手动纠正入口，不能把自动识别描述为任意文本都能无误识别。

导入使用 8/16 KiB 缓冲；章节标题行最多暂存 512 个 UTF-16 单元，最多索引 10,000 个标题。超长无换行正文不会作为一整行装入内存，仍完整写入缓存。不可解码输入和二进制 NUL 被拒绝，不发布半个书库记录。

原始副本加缓存会使用额外磁盘空间。纯 ASCII 约为原文件的 3 倍，常见中文 UTF-8 约为 1.7 倍，另有少量索引和数据库开销。可获得来源大小时，导入前保守检查可用空间；写入失败同样走清理和错误提示。

## 定位与分页

TXT 定位 v1 是 `(bookId, normalizedUtf16Offset)`，偏移以归一化正文的 UTF-16 单元计数，不使用页码。数据库保存 `locator_version=1`。换行归一化规则改变时必须升级缓存与定位约定。

排版通常读取约 8,192 单元，必要时增至最多 16,384 单元；窗口尾部未完成的页接续排版，不暴露读取截断处的字符/行边界。`StaticLayout` 依实际宽高、字体、字号和行距生成行，再按可用高度切成页面。最多缓存三个布局窗口与 1024 个仅含偏移的页范围；普通随机定位仍使用保护字符簇的有界起点，空文本有独立的可返回状态。

每页逻辑范围为 `[start,end)`。下一页从前页 `end` 开始；返回前页会得到相同范围。字号、主题或信息栏改变时，使用当前正文偏移重新查找包含该锚点的页面。绘制只使用已生成布局，磁盘和排版不进入 `onDraw`。

M1 至 M2.5 的固定窗口短页限制已在 M3 修正；书尾及显式跳转所形成的边界仍可有自然不足一屏的页面。不能以丢字或重复换取满页。超长异常组合字符串、复杂双向排版和更多自定义字体组合未在本轮扩展穷举。

## 持久化与故障边界

页面显示后异步提交位置；诊断快照区分当前位置与最后提交位置。停止翻页并确认提交后，强制停止应用应恢复相同正文位置。尚未提交就异常中断时，允许恢复到最后一次完整事务；正常生命周期回调不能作为断电时必然执行的保障。

来源文件修改不会改变已有私有原件。M2 支持从原件安全重建损坏/清理后的缓存，并可指定编码；原始字节和内容 ID 保持不变。索引检查版本、数量、单调偏移与缓存长度，有缓存校验值时检查正文哈希。旧缓存缺少校验值时先核验结构和原件身份，按可用空间补充侧文件；不能追溯补充之前的同长度正文损坏。编码变化按阅读比例近似映射进度和书签，位置可能略有变化。

M2 数据库 v2 显式从 v1 增加排序索引，不清库。缓存替换使用 `.rebuild-<id>-<token>` / `.previous-<id>-<token>`，目录同步后提交数据库，启动按目录和数据库状态恢复。删除使用 `.delete-<id>-<token>` 记录显式删除意图，联动封面与书签；不删除外部来源文件。清理缓存先核验可重建原件，保留当前阅读书。重复导入按原始字节身份去重，保留已有编码、标题和定位，不以自动解码结果覆盖用户纠正。

应用导入目录的清理只接受所属目录内直接普通文件，逐一选择并确认；拒绝外部路径和符号链接。封面、单份自定义字体分别保存和管理，不与 TXT 缓存混用。

APK 升级沿用独立签名和应用 ID。M0 样例页号不会迁移为真实书籍位置，M0 的字号、主题、亮度和信息栏设置可迁移。正式数据库后续改动需显式版本迁移，禁止失败后清库重建。
