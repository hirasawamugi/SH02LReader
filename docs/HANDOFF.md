## M1 试用反馈：两项改进的可行性分析（2026-10-18）

用户要求先分析，下列内容是设计建议，尚未修改产品代码或来源文件。

1. 按键帮助：当前 `MainActivity.buildContent()` 将说明作为单段文字显示，`help()` 增加一个“返回”条目；0 始终解析为打开帮助，相同页面的 push 被忽略，因此没有再次按 0 关闭的逻辑。用户提出改用 SH-02L 按键线稿和短说明，并用 0 反复开关，适合纳入 M1.5。建议依据用户提供的外观图及官方说明书（https://www.docomo.ne.jp/binary/pdf/support/manual/SH-02L_J_QSG.pdf）绘制按键区正视矢量图，功能标注仍以本工程实际键值和界面上下文为准。F1/F2/F3/F4 分别是菜单/相机/邮件/网络四个物理按键。0 打开/关闭需保留原焦点与正文锚点，抬起和长按不重复切换，F2/F4 保留返回；M2 的输入上下文中 0 仍用于输入数字。
2. 私有书库与移动导入：源码使用 `getFilesDir()/books/<SHA-256>/`，属于应用内部用户数据；每本包含 `original.bin`、`text.u16` 和 `index.bin`，外部源文件另行保留。正文有界读取，文件体积不会等量进入 RAM；原始副本加正文缓存的磁盘开销约为 ASCII 原文的 3 倍、常见中文 UTF-8 的 1.7 倍，另加少量索引和数据库，来源文件未计入这些倍数。移动能消除来源处的重复 TXT，但不会消除内部正文缓存。现有应用只申请读取共享存储，导入接口尚未保留完整的来源删除能力，不能把能选取/读取文件视为已可安全移动。建议 M2 书库管理评估“复制导入/移动导入并记住偏好”：完整导入、校验和数据库提交成功后，确认来源未变化且具备删除权限才删除；失败、取消、权限不足或提供程序不支持删除时保留源文件，准确提示结果。Android 文档提供程序需支持删除并有相应 URI 授权（https://developer.android.com/training/data-storage/shared/documents-files#delete）。私有副本随清除应用数据/卸载移除，移动方案应同时考虑导出原 TXT、书库占用显示和升级数据回归；删除来源属于待设计的显式导入模式，不改变 M1 当前“保留原文件”的约定。

## M2 必须处理：书架规模与低存储保护（方案待实现）

用户已同意提供“复制导入 / 移动导入”两种方式，并要求同时解决书籍数量增长和存储接近满时的运行、进度保存问题。此前反馈中的两种导入方式由候选转为已确认范围；具体保护机制仍是待实现的设计方案，不能把这些措施记为 M1 已具备。

源码核对发现：`BookRepository.list()` 将全部书籍读入 ArrayList，`MainActivity.loadLibrary()` 再生成全部列表项；当前只有 View 复用，没有数据分页。`ProgressWriter.drain()` 在写入前移除任务，失败后只回调错误，没有保留待重试进度。现有导入空间检查仅在来源大小已知时于导入开始执行一次（源大小四倍加 8 MiB），没有覆盖未知大小、导入过程中空间被其他应用占用或数据库提交阶段的保护。

- 书架采用匹配排序的数据库索引和游标分批查询，先以每批 32 本、至多当前及相邻两批作为设计起点；书架仍可连续按键浏览。最近阅读按书籍 ID 单独查询，总数独立获取；返回书架按书籍 ID 与滚动锚点恢复，避免每次读入全库或扫描所有正文目录。新增/删除/最近阅读顺序变化时使相关批次失效；后台结果仍检查任务代号，防止焦点跳到错误书籍。索引变化需显式数据库迁移并保留 M1 数据。
- 导入预算覆盖原始副本、正文缓存、索引、临时文件和数据库提交开销，并保留安全余量；对已知和未知来源均在复制/解码过程中按实际写入量检查可用空间。触及保护线时停止导入并清理本次未提交文件，移动模式不删除来源；保护线与应急空间不被当作可用的导入预算。书库元数据仅随变更更新，空间统计在后台按需执行，不在每次启动递归遍历所有书籍。
- 进度写入优先于新增导入和缓存重建。预先分配小型私有应急文件，写入空间不足时停止大任务，清理未完成导入、释放应急空间并有限重试最新进度；应急文件必须实际占用存储，不能仅创建稀疏文件。失败项保留最新待保存位置，重试有上限和退避，不能忙循环或覆盖更新的位置；恢复到足够空间后再补回应急文件和开放新导入。仍未提交时明确显示“进度尚未保存”，不报告保存成功。
- 提供书库总占用、原文/缓存占用和大文件管理入口；删除书籍仅操作用户选择的私有副本。派生正文缓存只有在原始副本完整、重建流程可用后才允许回收，并保留当前阅读图书；M1 的索引会检查 `text.u16`，当前不能直接删除缓存后继续当作有效书籍。回收过缓存的书籍在重开时仍需满足重建空间要求。
- 规模验收加入 1000 本书的书架查询、缓存上限、按键滚动和返回定位；低存储验收在隔离测试库/模拟器中覆盖来源大小未知、导入途中耗尽、数据库提交失败、进度写入失败及空间恢复。验证原文件和已有书籍不损坏，失败的进度保持待保存并在恢复后提交，移动来源不被过早删除；不为此填满用户日常手机的存储。

这些措施控制阅读器自身的增长并优先保护进度，但系统存储或硬件彻底不可写时仍不能承诺新进度必然落盘。这个边界须在测试报告中明确，不把空间检查或应急文件当作无条件保证。

2026-10-18 按用户反馈明确 M3 分工：长时间阅读由用户在日常使用中亲自验证，原“两小时”作为参考观察时长，可随日常使用累计；不安排 Codex 会话连续等待或自动操作两小时。用户观察卡顿、闪退、正文、按键与进度恢复；Codex 负责有界自动化回归、内存与耗时测量、日志检查和问题定位。工程检查通过后可交付候选版供用户试读；尚未收到反馈时将长期试读标为“待用户试读”，不宣称完整 M3 验收通过。

## 构建和发布

工具链为 AGP 8.6.1 / Gradle 8.7 / JDK 17 / compile-target 35 / min 27，无 NDK、AndroidX 或网络运行时依赖。项目工具与 SDK 位于 `tools/`，复用本机已安装 JDK 17，构建脚本只设置进程环境。不要改全局 Java。

```powershell
.\scripts\build.ps1 -Task verify
.\scripts\build.ps1 -Task release
.\scripts\test-device.ps1 -Serial <明确设备编号> -Label <标签>
.\scripts\smoke-release.ps1 -Serial <明确设备编号> -Label <标签>
.\scripts\publish-local.ps1
```

`test-device` 安装并操作独立 debug/test 包；运行时会唤醒设备。不要与用户正在进行的手测或同一设备上的其他自动输入并行。`smoke-release` 只适用于应用导入目录含两份生成夹具的情况，避免选到用户的其他文件。

发布脚本要求干净的已提交源码，验证签名/版本/对齐，并保护已有版本不可被不同 APK 覆盖。下一阶段改代码时递增版本，不重写 `v0.2.0-m1`。签名凭据在被忽略的 `tools/signing/`，需保留，不输出密码、不提交到 Git。缓存和 SDK、日志、发布包均被忽略，源码和文档已提交。
